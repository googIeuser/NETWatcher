# Code of Conduct

NetWatcher welcomes people of every background and experience level. These rules apply to issues, pull requests, reviews, and other project spaces, including interactions where someone represents the project.

## Expected behavior

- Be respectful, patient, and constructive; help newcomers participate.
- Critique ideas and code with specific evidence rather than personal attacks.
- Respect different backgrounds, identities, abilities, and opinions.
- Keep discussions relevant, accept feedback, and correct mistakes.
- Protect privacy. Remove sensitive details from logs, reports, and screenshots.

Harassment, threats, discriminatory insults, sexualized conduct, doxxing, impersonation, spam, and repeated disruption are not allowed. Do not publish another person's private information without permission. Respectful disagreement about technical decisions is welcome.

## Reporting concerns

Musa ([googIeuser](https://github.com/googIeuser)) maintains and moderates this project. To request maintainer attention, open a brief, non-sensitive issue with links to relevant public project content. If details require privacy, ask for a private contact channel first; do not publish private conversations or personal information.

For violations of GitHub's rules, use **Report content → Report abuse to GitHub Support**, following [GitHub's reporting guide](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam). Reports sent to GitHub Support go to GitHub, not directly to the maintainer. Security vulnerabilities belong in the [private security channel](https://github.com/googIeuser/NETWatcher/security/advisories/new), following [SECURITY.md](SECURITY.md).

## Moderation and reconsideration

The maintainer may request corrections, remove or hide content, close or lock discussions, or restrict participation. Decisions should consider severity, impact, and repeated behavior. Serious threats or harassment may lead to immediate restrictions. The rules apply to everyone, including the maintainer.

An affected person may request reconsideration with relevant context through a non-sensitive issue or an agreed private channel. Reports are shared only as needed for moderation. Public issues remain public; never use them for confidential details. No response deadline is promised, and this policy does not replace GitHub's own reporting process.
