# NETWatcher 5.1.6

This update lowers NetWatcher's CPU and memory use during long monitoring sessions. On Windows, IPv4 ping targets are now checked through the system ICMP service instead of starting a separate ping program on every check, and the default gateway is read directly from Windows. Ping times are measured more precisely, and a reply such as "destination host unreachable" now counts as a failed check.

The chart history is updated one point at a time instead of being rebuilt on every check, and it uses less memory. The interface receives only new events on each refresh and redraws only the parts that changed. Log files are read row by row when the app starts, when the chart range is widened, and when reports are created. Slow name lookups for TCP and ping targets can no longer delay a check beyond the configured timeout.
